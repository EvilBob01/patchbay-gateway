Servers

A server is a backend this gateway connects to — one source of capabilities, like an SSH host or another MCP service. Each server provides one or more tools (see the Tools tab). The list below is every backend the gateway aggregates and hands to your Claude clients as a single connection.

New here? The easiest way to add a backend is the Add Server (Wizard) button below — it walks you through it and can even install this gateway's SSH key on the target host for you. Any change here only goes live after you click Save & Reload.

Tools

A tool is a single capability a server provides — for example an SSH backend exposes an exec tool. One server usually offers several tools, and clients see them namespaced like servername__toolname. Here you can turn individual tools on or off for everyone without removing the whole server — handy for hiding something risky like sudo-exec.

Ordering matters here. Unlike the Servers tab, the order and grouping you set below is also the order tools are advertised to Claude clients. Keeping it stable helps the model's prompt cache; putting the tools you use most near the top doesn't hurt either. Anything you haven't placed is sorted alphabetically after the rest.

Users

Each person who connects to this gateway gets their own token — a secret string that acts as their key. There's no separate login for regular users; the token in their config is the credential, so you can revoke one person's access without affecting anyone else. Create a user below, then hand them a config with Copy Desktop Config or the one-click Download Installer.

Tool access policy

Which users may see and call which tools. With no policy saved, everyone gets every enabled tool. Patterns are * or server/tool, where * is a wildcard (e.g. forgejo/*, */read-command); deny beats allow. Keys: default (anyone not listed), static (the shared env key), users (by username) and named roles. Saved changes apply to the next request — no restart.

Generate Claude Desktop config

Click Copy Desktop Config on any user above to build a ready-to-paste block for their Claude Desktop app (Windows or Mac). Paste it into Settings → Developer → Edit Config. Their machine needs Node.js installed (node -v to check) and network access to this gateway.

Mailboxes

Mailboxes registered here are what the mail MCP server (imap-mcp) exposes to Claude -- one config, every account. Credentials are encrypted at rest in this gateway's own config and are never shown back in this UI once saved. Saving or deleting a mailbox restarts just the mail connector (a second or two); every other tool on this gateway is unaffected.

Deploy SSH Key to a New Host

To connect to an SSH backend, this gateway signs in with its own SSH key — but the target host has to trust that key first. This one-shot tool does that for you: it connects to the host once with a password, appends the gateway's public key to that account's authorized_keys, and immediately discards the password (it's never stored or logged). After this, the gateway can reach the host with no password. The Add Server wizard can run this step for you automatically.

Help & how-to

This gateway bundles a bunch of separate backend servers into one connection for your Claude apps. Below is how to run it, and a glossary of the jargon.

The 30-second version: add a backend on the Servers tab, create a person on the Users tab, then hand them the installer. They double-click it, restart Claude Desktop, and every backend shows up as tools — no config editing on their end.

What is this thing?

Normally each MCP backend (each SSH host, each service) would be its own entry in every person's Claude Desktop config. That's a lot of duplicated setup and a fat context window. This gateway connects to all of them once, on the server side, and presents them to clients as a single MCP connection. Add a backend here and it instantly appears for everyone — nobody has to touch their config.

How to…

Add a new backend server

  1. Go to the Servers tab and click Add Server (Wizard).
  2. Pick the type. For an SSH host, choose SSH host and enter its address, the SSH username, and port (usually 22).
  3. If the host doesn't trust this gateway's key yet, the wizard can install it for you (you'll enter that account's password once — it's used once and discarded).
  4. Review and click Finish. The wizard saves and reloads; the new backend's tools appear for connected clients.

Onboard a person (the easy way)

  1. On the Users tab, type their name and click Create User.
  2. Click Download Installer next to them. You get a small .zip.
  3. Send them the zip. They unzip it, double-click Install.bat, and restart Claude Desktop. Done — nothing else to install (Node is bundled).
  4. Need to cut someone off? Click Revoke. Their token stops working immediately; nobody else is affected.

Turn a tool off for everyone

  1. Go to the Tools tab.
  2. Untick the tool you want to hide (e.g. a sudo-exec).
  3. Save & reload. The tool disappears from clients but the server stays connected.

Glossary

MCP (Model Context Protocol)
The open standard Claude uses to talk to external tools and data. An MCP server advertises capabilities; an MCP client (like Claude Desktop) calls them.
Gateway / proxy
This app. It's an MCP server to your clients and an MCP client to all the backends — aggregating many servers behind one connection.
Server (backend)
One capability source the gateway connects to — an SSH host, a database service, etc. Managed on the Servers tab.
Tool
A single callable function a server exposes (e.g. exec). One server → many tools. Clients see them as servername__toolname.
Prompt / Resource
Two other things an MCP server can expose besides tools: reusable prompt templates, and readable data resources. This gateway supports passing them through, though most backends here only provide tools.
Token
A per-user secret that authenticates a client to this gateway. It goes in the client's config URL as ?key=…. Created and revoked on the Users tab.
stdio / SSE / HTTP
How the gateway talks to a backend. stdio launches a local command and talks over its input/output (used by SSH backends). SSE and HTTP connect to a backend that's already running at a URL.
ssh-mcp
The small program the gateway runs (as a stdio server) to turn an SSH host into MCP tools. Most backends here are ssh-mcp pointed at a host.
Deploy Key
Installing this gateway's SSH public key onto a host so the gateway can log in without a password. Done via the Deploy Key tab or automatically by the wizard.
